# Deploying AVELLE to Render

## Before the first deploy
1. Generate migrations locally and commit them (they are not in this repo by design):
   `python manage.py makemigrations core accounts catalog cart wishlist orders payments promotions notifications content dashboard`
2. Run `python manage.py test` and `python tools/run_checks.py` and fix any failures.
3. Push to GitHub.

## Create the services
- **Blueprint:** in Render choose New > Blueprint and point it at the repo. `render.yaml` defines the web service
  (`avelle`) and a daily cron job (`avelle-expire-unpaid`, 03:00 UTC).
- Or create them by hand with the same build/start commands.
- Your existing Render PostgreSQL: copy its **Internal Database URL** into `DATABASE_URL` on both services.

## Environment variables (set on the web service; the cron job needs the same ones)
| Variable | Value |
|---|---|
| `DJANGO_SETTINGS_MODULE` | `config.settings.prod` |
| `DJANGO_SECRET_KEY` | generated by the blueprint (the cron job reads the web service's) |
| `DATABASE_URL` | Internal Database URL |
| `DJANGO_ALLOWED_HOSTS` | your domain(s), comma separated (the `*.onrender.com` host is added automatically) |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | `https://yourdomain.com` |
| `SITE_URL` | `https://yourdomain.com` (used in emails and Paystack callbacks) |
| `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, `CLOUDINARY_API_SECRET` | from Cloudinary |
| `PAYSTACK_SECRET_KEY` | **live** key (`sk_live_...`) once you go live; `sk_test_...` while testing |
| `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`, `DEFAULT_FROM_EMAIL` | SMTP provider |

## After the first deploy
1. Create your first administrator: Render Shell on the web service, then `python manage.py createsuperuser`
   (superusers get full dashboard access at `/dashboard/`).
2. In the Paystack dashboard (Settings > API Keys & Webhooks) set the webhook URL to
   `https://yourdomain.com/payments/webhook/`. Check the exact path in `apps/payments/urls.py`.
   Paystack signs webhooks with your secret key; the app verifies the signature.
3. Add delivery charges (Dashboard > Delivery charges, "Add them"), categories, products, homepage content.
4. Walk through the manual checklist in `TESTING.md` using Paystack test keys before switching to live keys.

## What the build does (`build.sh`)
- installs requirements;
- `fetch_vendor` downloads GSAP 3.12.5 into `static/vendor/gsap/` so pages don't depend on a CDN
  (if the download fails, pages fall back to the pinned CDN copy and the build still succeeds);
- `collectstatic` (WhiteNoise compresses and fingerprints files, so they cache for a long time);
- `migrate`.

## Performance
- Static files: WhiteNoise with compressed, hashed names.
- Images: Cloudinary URLs get `f_auto,q_auto,c_limit,w_N` through the `|cdn:N` template filter (WebP/AVIF where
  supported, width capped). Images keep `width`/`height` attributes and `loading="lazy"` (the hero is eager).
- Database connections are kept for 10 minutes with health checks.
- Health check: `/healthz/` (checks the database; exempt from the HTTPS redirect).

## Known limits / next steps
- No Content-Security-Policy header yet: the site uses Google Fonts and inline JSON-LD, so a policy needs testing
  against the live pages first.
- HSTS is set to 30 days. Raise it to a year once you're sure HTTPS works everywhere.
- The cache is per-process (LocMem); newsletter rate limiting is therefore per worker. Use Redis if you scale out.
- The `starter` plan in `render.yaml` is a suggestion; use the plan you have.
- Nothing here has been deployed or run against a real Render service from my side.

## Payments that were paid but show "not completed"

Paystack tells the site about a payment in two ways: the customer's browser returns to /payments/callback/, and
Paystack calls /payments/webhook/ itself. Customers who pay by bank transfer often close the page, so only the
webhook can mark the order paid. Check, in Paystack > Settings > API Keys & Webhooks (set it for **Live** mode too):

- Live Webhook URL is exactly `https://avelle.onrender.com/payments/webhook/` (https, trailing slash, no www).
- Render's `PAYSTACK_SECRET_KEY` is the **live** secret key (`sk_live_...`) that belongs to the same Paystack account.
- In Render > Logs, a delivery shows as `POST /payments/webhook/ 200`. 401 means the wrong key, 301 means http or a
  missing slash, 400 means ALLOWED_HOSTS.

Safety nets built in: the order page re-checks Paystack whenever it is opened, customers and staff have a
"Check payment" button, and `python manage.py reconcile_payments` (cron every 10-15 minutes on Render) fixes any
unpaid order from the last 3 days that Paystack shows as paid. Orders are never cancelled for non-payment without
asking Paystack first (`expire_unpaid_orders`).
